
# Exercise 3 - Overflow

## Question 1 - Predictions and Actual Results

The original array is:

`x = np.array([100, 200, 250], dtype=np.uint8)`

| Expression | My Guess | Actual Result |
|------------|----------|---------------|
| x + 10 | Add 10 to every value | [110, 210, 4] |
| x + 100 | Add 100 to every value | [200, 44, 94] |
| x - 150 | Subtract 150 from every value | [206, 50, 100] |
| x * 2 | Multiply every value by 2 | [200, 144, 244] |
| x.astype(np.int16) + 100 | Convert to int16 and add 100 | [200, 300, 350] |
| x * 1.5 | Multiply every value by 1.5 | [150.0, 300.0, 375.0] |
| (x * 1.5).dtype | Unknown | float64 |

### Explanation

The array uses uint8, which stores integer values from 0 to 255.

When an arithmetic result exceeds 255 or becomes negative,
overflow occurs in the uint8 arithmetic operations.

For example:

- 250 + 10 = 260, but the result is 4.
- 200 + 100 = 300, but the result is 44.
- 100 - 150 = -50, but the result is 206.
- 200 * 2 = 400, but the result is 144.

Converting the array to int16 before adding 100 prevents
overflow in this calculation.

Multiplying by 1.5 produces a float64 array,
which can represent decimal values.


## Question 2 - Adding 300

Expression:

`print(x + 300)`

Prediction: Overflow

Actual result: OverflowError

### Explanation

NumPy raises an OverflowError because 300 cannot
be represented as a uint8 scalar.

The maximum value of uint8 is 255.

Unlike adding 100, adding 300 causes an error
when NumPy tries to convert the scalar to uint8.


## Question 3 - Safe Addition

The function add_safe(x, b) adds b to each value
without allowing the final result to exceed
the range from 0 to 255.

It first converts the array to int16,
then adds b and uses np.clip to limit the values.
Finally, it converts the result back to uint8.

### Test with b = 100

Original array: [100, 200, 250]

Calculation: [200, 300, 350]

Actual result: [200, 255, 255]

Values greater than 255 are limited to 255.

### Test with b = -150

Original array: [100, 200, 250]

Calculation: [-50, 50, 100]

Actual result: [0, 50, 100]

Negative values are limited to 0.


## Question 4 - Why np.clip(x + 100, 0, 255) Is Not Enough

Overflow happens during x + 100, before np.clip is applied.

Some values exceed 255 and wrap around because
the array uses uint8.

For example, 200 + 100 produces 44 instead of 300.

After overflow, np.clip cannot recover
the original value.

Therefore, the array must be converted to a larger
integer type before adding 100.


## Question 5 - Bonus: int8 Overflow

The range of int8 is from -128 to 127.

Prediction: 127 + 1 = -128

Actual result: -128

### Explanation

int8 uses 8 bits and supports both positive
and negative integers.

When adding 1 to 127 using int8 arithmetic,
the result exceeds the maximum value.

Overflow occurs, and the result wraps around to -128.
